## 1. 插件机制概览

ZeroAuth 采用**文件驱动的插件系统**：系统启动时自动扫描 `/plugin/*/Plugin.php`，每个目录即一个插件。插件无需注册到任何地方，**放入目录即可被识别**，再到后台「应用商店」中启用。

## 2. 插件上传位置（重要）

```
网站根目录/
└── plugin/                 ← 插件统一上传到这个目录
    ├── epay/               ← 内置支付插件
    ├── turnstile/          ← Turnstile 验证插件
    ├── rainbow/            ← 彩虹聚合登录插件
    └── 你的插件目录/        ← ← ← 新插件上传/创建在这里
        ├── Plugin.php      ← 必需：插件元数据
        ├── icon.svg        ← 建议：商店图标
        └── ...             ← 其他业务文件
```

- 通过 FTP / 宝塔文件管理器 / SSH，把整个插件目录上传到 **`网站根目录/plugin/`** 下；
- 目录名建议与插件 `code` 一致（小写字母、数字、下划线）；
- 上传后进入后台 **「应用商店」**，即可看到新插件，点击「启用」并「配置」参数；
- `runtime/`、`uploads/` 目录保持可写，插件敏感配置（password 类型字段）会自动加密迁移到数据库 `sys_config` 表。

## 3. Plugin.php 元数据

`Plugin.php` 必须直接 `return` 一个数组：

```php
<?php
// 插件元数据
declare(strict_types=1);

return [
    'code' => 'myplug',              // 必需，全局唯一标识
    'name' => '我的插件',             // 显示名
    'cat'  => 'pay',                 // 分类：pay支付 / template主题 / captcha验证 / login登录 / realname实名
    'description' => '插件功能说明…',
    'version' => '1.0.0',
    'author'  => '你的名字',
    'core'        => 0,              // 1=核心内置（不可卸载）
    'installable' => 1,              // 1=允许安装
    'status'      => 2,              // 默认状态：1启用 2停用（未配置过时生效）
    'sort'        => 50,             // 排序，数值越小越靠前
    'config' => [                    // 后台「配置」表单，可为空数组
        [
            'key'   => 'my_key',     // 配置键（读取时使用）
            'label' => '配置名称',
            'type'  => 'text',       // text / password / select / switch / textarea
            'hint'  => '输入框下方提示',
            'options' => ['a' => '选项A', 'b' => '选项B'],  // 仅 select
            'default' => 'a',                               // 仅 select
        ],
        [
            'key'   => 'my_secret',
            'label' => '密钥',
            'type'  => 'password',   // password 类型 = 敏感配置，自动存入 sys_config，界面只写不改
            'hint'  => '已配置则留空保持不变',
        ],
    ],
];
```

> 注意：`config` 中非敏感字段（text/select/switch/textarea）的值会自动合并进全局 `cfg()` 缓存，因此代码里可以直接 `cfg('my_key')` 读取；敏感字段必须用 `plugin_cfg_get('myplug', 'my_secret')` 读取。

## 4. 可用的框架函数

插件业务文件（如 `pay.php`、`entry.php`）头部标准写法：

```php
<?php
declare(strict_types=1);
require dirname(__DIR__, 2) . '/core/bootstrap.php';   // 回到根目录的 core/bootstrap.php
require_once ROOT_PATH . '/core/Security.php';
config();                                               // 未安装时会自动跳转安装提示
```

常用 API（均定义于 `core/bootstrap.php` / `core/PluginSys.php` / `core/Captcha.php`）：

| 函数 | 说明 |
| --- | --- |
| `e($str)` | HTML 转义输出 |
| `db()` | 获取 PDO 实例（utf8mb4，异常模式） |
| `cfg($key, $default)` | 读全局配置（已合并启用插件的普通配置） |
| `set_cfg($key, $value, $remark)` | 写全局配置 |
| `plugin_enabled($code)` | 插件是否处于启用状态 |
| `plugin_cfg_get($code, $key, $default)` | 读取插件配置（含敏感字段） |
| `plugin_cfg_set($code, $kv数组)` | 批量写插件配置 |
| `plugin_scan()` / `plugin_all()` | 扫描/列出全部插件元数据 |
| `client_ip()` | 客户端真实 IP（开启「真实IP获取」后自动解析 CF/X-Real-IP/X-Forwarded-For） |
| `http_get($url, $timeout)` / `http_post($url, $body, $headers, $timeout)` | HTTP 请求（cURL 优先，失败回退 file_get_contents） |
| `audit($module, $action, $actorType, $actorId, $detail)` | 写审计日志 |
| `csrf_field()` / `csrf_check()` | 表单 CSRF |
| `json_out($code, $msg, $data)` | 输出 JSON 并结束 |
| `flash_set($type, $msg)` / `flash_take()` | 一次性提示消息（type: ok/err） |
| `redirect($url)` | 302 跳转 |
| `sec_rate_hit($channel, $ip, $threshold)` | 基于 IP 的每分钟限流 |

## 5. 验证码类插件开发约定

ZeroAuth V2.0 将验证码抽象为三级模式（`core/Captcha.php`）：

```
Turnstile 插件启用 → captcha_mode() = 'turnstile'
否则 极验插件启用  → captcha_mode() = 'geetest'
否则               → captcha_mode() = 'image'（内置 GD/SVG 图形验证码）
```

**极验插件**（`plugin/geetest/`）配置键：`geetest_captcha_id`、`geetest_captcha_key`（password）。
**Turnstile 插件**（`plugin/turnstile/`）配置键：`turnstile_site_key`、`turnstile_secret_key`（password）。

开发其他验证码插件时请遵循：

1. `Plugin.php` 中 `cat` 设为 `captcha`；
2. 校验逻辑：接收表单 token → 调用服务商 API 二次校验 → 返回布尔结果；
3. 如需接入统一场景校验（推荐），在 `core/Captcha.php` 中按 Turnstile 的实现方式扩展 `captcha_mode()` 与 `captcha_verify_scene()`；
4. 场景开关：`captcha_scene_on($scene)` 控制，`register` 场景受后台「验证与真实IP → 注册验证码」开关控制，其余场景恒开。

## 6. 登录（OAuth）类插件开发约定

参考实现：`plugin/rainbow/`（彩虹聚合登录）。推荐结构：

```
plugin/rainbow/
├── Plugin.php     # cat => 'login'，配置：appid/appkey/接口地址/启用方式/自动注册
├── common.php     # 类型表、配置读取、绑定表懒创建（rainbow_table_ensure）
├── entry.php      # 入口：服务端请求 act=login 拿跳转 URL → 302 跳第三方
└── callback.php   # 回调：act=callback 换用户信息 → 登录/绑定/自动注册
```

要点：

1. **回调地址**固定为插件内文件：`base_url() . 'plugin/rainbow/callback.php'`，需填入服务商开放平台；
2. 绑定关系建议自建表（`CREATE TABLE IF NOT EXISTS` 懒创建即可，无需改安装 SQL）；
3. 登录成功后：`session_regenerate_id(true)` → `$_SESSION['user_id'] = $uid` → `redirect('../user/dashboard.php')`；
4. 已登录用户发起绑定：优先读 `current_user()`，绑表后跳 `../user/profile.php`；
5. 前台登录页按钮展示：调用插件的 `rainbow_active_types()` 判断并渲染（见 `user/index.php` 中的 `$oauthTypes` 示例）。

彩虹聚合登录接口（供自实现参考）：

- 获取跳转：`GET {api}/connect.php?act=login&appid=&appkey=&type=qq&redirect_uri=`，返回 `{code:0, url:"..."}`
- 回调换信息：`GET {api}/connect.php?act=callback&appid=&appkey=&type=&code=`，返回 `{code:0, social_uid, nickname, faceimg, ...}`
- 查询用户：`GET {api}/connect.php?act=query&appid=&appkey=&type=&social_uid=`

## 7. 支付类插件开发约定

参考实现：`plugin/epay/`、`plugin/alipay/`、`plugin/wechat/`。约定：

1. `cat` 设为 `pay`，业务入口文件为 `pay.php`；
2. 公共函数（HTTP/签名）可复用 `require_once __DIR__ . '/../common/common.php';`；
3. 异步通知回调里验证签名后，更新订单状态并返回平台要求的响应体。

## 8. 数据库与升级

- 安装期建表：`install/schema.sql`（仅系统核心表）；
- 已安装系统的表结构变更：写入 `core/schema_upgrade.php` 的 `schema_upgrade_boot()`，系统每次启动自动比对执行（插件表建议运行时懒创建）；
- 插件自身的运行日志请写入 `runtime/` 下自有文件，勿污染根目录。

## 9. 上架检查清单

- [ ] `Plugin.php` 语法正确，`code` 全局唯一，`php -l Plugin.php` 通过；
- [ ] 目录已上传至 `网站根目录/plugin/插件目录/`；
- [ ] 应用商店中可见、可启用、可配置、可停用；
- [ ] 敏感字段使用 `password` 类型；
- [ ] 所有输入经 `e()` 转义或参数化查询，无 SQL 注入/XSS；
- [ ] 已在文档中注明回调地址与配置方法；
- [ ] **保留系统版权信息与「关于系统」页面入口。**
