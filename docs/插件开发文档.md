# ZeroAuth 插件开发文档（全新版）

> 适用版本：ZeroAuth V2.0+（内核 2.0）　文档版本：2026.11
> 作者：APE开发项目组-玄猿工坊　官方 QQ 群：882138945
> **发布插件请保留系统版权信息与「关于系统」入口。**

本版为全新重写版：先给出最小可运行流程，再说明元数据、生命周期、框架 API 与各分类插件约定。

---

## 1. 插件系统机制

- **文件驱动**：系统扫描 `plugin/*/Plugin.php`，返回数组即注册一个插件，无需写数据库或注册中心；
- **即放即识别**：目录上传后刷新后台「应用商店」即可看到；
- **状态存库**：启用 / 停用 / 卸载状态保存在 `plugin` 表，配置保存在 `plugin` 表或 `sys_config`；
- **分类展示**：应用商店按 `captcha / login / pay / realname / template` 分类筛选；
- **共享库**：`plugin/common/` 是无 `Plugin.php` 的公共代码目录，不会被识别为插件。

## 2. 最小可运行流程

```text
1) 新建目录：网站根目录/plugin/myplug/
2) 写入 Plugin.php（返回元数据数组）
3) 需要业务页面时再添加 entry.php / pay.php / home.php 等文件
4) 后台「应用商店」→ 安装 → 配置 → 启用
```

## 3. 目录与上传位置

```text
网站根目录/
└── plugin/
    ├── common/                 ← 公共代码（不是插件）
    ├── epay/                   ← 支付插件
    ├── turnstile/              ← 验证插件
    ├── rainbow/                ← 第三方登录插件
    ├── tpl_v2/                 ← 首页模板插件
    └── myplug/                 ← 你的插件
        ├── Plugin.php          ← 必需：元数据
        ├── icon.svg            ← 建议：应用商店图标
        └── ...                 ← 业务文件
```

- 通过 FTP / 宝塔文件管理器 / SSH 上传整个插件目录；
- 目录名建议与 `code` 一致（小写字母、数字、下划线）；
- 目录名与 `code` 可以不同，系统以 `Plugin.php` 返回的 `code` 为准，实际目录通过 `plugin_scan()['dir']` 获取。

## 4. Plugin.php 元数据

```php
<?php
declare(strict_types=1);

return [
    'code'        => 'myplug',          // 必需，全局唯一
    'name'        => '我的插件',         // 应用商店显示名
    'cat'         => 'pay',             // captcha/login/pay/realname/template
    'description' => '插件功能说明',
    'version'     => '1.0.0',
    'author'      => '你的名字',
    'core'        => 0,                 // 1=核心内置，不可卸载
    'installable' => 1,                 // 1=允许安装
    'status'      => 2,                 // 默认状态：1启用 2已安装停用 3未安装
    'sort'        => 50,                // 数值越小越靠前
    'config'      => [                  // 可为空数组
        [
            'key'     => 'api_url',
            'label'   => '接口地址',
            'type'    => 'text',
            'hint'    => '服务商接口根地址',
            'default' => 'https://example.com',
        ],
        [
            'key'   => 'api_secret',
            'label' => '接口密钥',
            'type'  => 'password',      // 敏感项：不回填、留空保持不变
            'hint'  => '仅服务端使用',
        ],
    ],
];
```

### 4.1 字段说明

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `code` | 是 | 全局唯一标识，建议小写 |
| `name` | 是 | 应用商店与列表显示名 |
| `cat` | 是 | 分类，决定商店筛选与优先级逻辑 |
| `description` | 否 | 插件说明 |
| `version` | 否 | 插件版本号 |
| `author` | 否 | 作者，含「官方」可显示官方角标 |
| `core` | 否 | 1 表示核心插件，仅可停用不可卸载 |
| `installable` | 否 | 1 表示可在商店安装；0 显示「待上架」 |
| `status` | 否 | 无数据库记录时的默认状态 |
| `sort` | 否 | 同分类排序，数值越小越靠前 |
| `config` | 否 | 后台配置表单字段数组 |

### 4.2 分类 `cat`

| 值 | 用途 |
| --- | --- |
| `captcha` | 行为验证 / 人机验证 |
| `login` | 第三方登录（OAuth） |
| `pay` | 支付方式 |
| `realname` | 实名认证服务商 |
| `template` | 首页主题，详见《主题开发文档》 |

## 5. 配置项

### 5.1 字段类型

| `type` | 表单控件 | 提交规则 |
| --- | --- | --- |
| `text` | 单行文本 | 原样保存 |
| `password` | 密码框 | 留空表示不修改；非空才写入 |
| `select` | 下拉框 | 需提供 `options` 数组，可用 `default` |
| `switch` | 开关 | 提交 `1` / `0` |
| `textarea` | 多行文本 | 原样保存 |

### 5.2 读取与保存

```php
// 普通配置：同时会合并进全局 cfg()（键名建议加插件前缀，避免覆盖）
$apiUrl = plugin_cfg_get('myplug', 'api_url', 'https://example.com');
$apiUrl = cfg('api_url', 'https://example.com');

// 敏感配置：只从 sys_config 对应键读取，后台不回填
$secret = plugin_cfg_get('myplug', 'api_secret', '');

// 批量写入（后台保存时由系统调用，插件一般无需手动写）
plugin_cfg_set('myplug', ['api_url' => $url, 'api_secret' => $secret]);
```

- 敏感项存储键为 `plugin_cfg_{code}_{key}`，写入 `sys_config`；
- 系统默认不对敏感项做额外加密；如需加密存储，请自行 `sec_encrypt()` 后保存、读取时 `sec_decrypt()`；
- 配置键名在不同插件间可能冲突，合并进 `cfg()` 时后写入者覆盖，因此务必使用带插件前缀的键名。

## 6. 插件生命周期

| 状态 | 含义 | 说明 |
| --- | --- | --- |
| `1` | 已启用 | `plugin_enabled($code)` 为 `true` |
| `2` | 已安装 / 已停用 | 可配置、可启用，功能入口不生效 |
| `3` | 未安装 | 仅 `installable = 1` 可安装 |

- 安装：`status` 置 2，随后跳转配置页；
- 启用：仅 `status = 2` 可启用；
- 停用：仅 `status = 1` 可停用；
- 卸载：`core = 1` 不可卸载，其余置 3；
- 模板插件互斥：启用一个模板时自动停用其他已启用模板。

## 7. 业务文件标准写法

插件内的独立入口文件（如 `entry.php`、`pay.php`、`callback.php`）建议：

```php
<?php
declare(strict_types=1);
require dirname(__DIR__, 2) . '/core/bootstrap.php';   // plugin/xxx/ → 网站根目录
require_once ROOT_PATH . '/core/Security.php';
config();                                              // 未安装时自动进入安装引导

if (!plugin_enabled('myplug')) {
    exit('插件未启用');
}
```

> `home.php` 由 `index.php` 直接 `require`，无需重复引入 `bootstrap.php`，详见主题文档。

## 8. 常用框架 API

| 函数 | 说明 |
| --- | --- |
| `e($str)` | HTML 转义 |
| `db()` | PDO 实例（异常模式、`utf8mb4`） |
| `cfg($key, $default)` | 读取全局配置（含普通插件配置） |
| `set_cfg($key, $value, $remark)` | 写入全局配置 |
| `plugin_enabled($code)` | 插件是否启用 |
| `plugin_scan()` | 扫描全部插件元数据 |
| `plugin_all()` | 列出插件（含运行状态与配置） |
| `plugin_cfg_get($code, $key, $default)` | 读取插件配置 |
| `plugin_cfg_set($code, array $kv)` | 批量写插件配置 |
| `client_ip()` | 真实客户端 IP（支持 CF / X-Real-IP / X-Forwarded-For） |
| `http_get($url, $timeout = 5)` | GET 请求，cURL 优先 |
| `http_post($url, $body, $headers = [], $timeout = 10)` | POST 请求 |
| `audit($module, $action, $actorType, $actorId, $detail)` | 写审计日志 |
| `csrf_field()` / `csrf_check()` | 表单 CSRF |
| `json_out($code, $msg, $data)` | 输出 JSON 并结束 |
| `flash_set($type, $msg)` / `flash_take()` | 一次性提示（`ok` / `error`） |
| `redirect($url)` | 302 跳转 |
| `sec_rate_hit($channel, $ip, $threshold)` | 每分钟 IP 限流 |
| `sec_verify_sign($params, $key)` | HMAC 签名校验 |
| `sec_check_timestamp($timestamp, $window)` | 时间戳有效期校验 |
| `sec_nonce_check($nonce, $ttl)` | nonce 一次性校验 |

### 8.1 数据库建议

- 插件表使用 `CREATE TABLE IF NOT EXISTS` 懒创建，表名加前缀（如 `myplug_log`）；
- 所有查询使用参数化，禁止拼接 SQL；
- 运行日志写入 `runtime/` 下的自有文件，不要写根目录或插件目录。

## 9. 验证码插件约定

验证码模式优先级：

```text
Turnstile 启用 → captcha_mode() = 'turnstile'
否则 极验启用  → captcha_mode() = 'geetest'
否则          → captcha_mode() = 'image'
```

- 统一校验入口：`captcha_verify_scene($scene, $_POST)`，返回 `[bool $passed, string $msg]`；
- 场景：`login`、`register`、`forgot` 等，可用 `captcha_scene_on($scene)` 判断开关；
- 内置插件配置键：
  - 极验：`geetest_captcha_id`、`geetest_captcha_key`（password）；
  - Turnstile：`turnstile_site_key`、`turnstile_secret_key`（password）；
  - 前台组件：`turnstile_script_html()`、`turnstile_widget_html($theme)`。

开发新验证码插件：

1. `cat` 设为 `captcha`；
2. 服务端二次校验服务商返回的 token；
3. 如需接入三端登录 / 注册 / 找回密码统一流程，在 `core/Captcha.php` 扩展 `captcha_mode()` 与 `captcha_verify_scene()`；
4. 校验失败必须返回明确提示，不要抛出未捕获异常。

## 10. 第三方登录（OAuth）插件约定

参考实现：`plugin/rainbow/`。

```text
plugin/rainbow/
├── Plugin.php     # cat = login，配置 appid/appkey/接口地址/登录方式/自动注册
├── common.php     # 配置读取、类型表、绑定表懒创建
├── entry.php      # 发起登录：服务端拿跳转地址 → 302 到第三方
└── callback.php   # 回调：换取用户信息 → 登录 / 绑定 / 自动注册
```

要点：

1. 回调地址固定为插件入口：`base_url() . 'plugin/rainbow/callback.php'`，需填写到服务商后台；
2. 绑定关系建议自建表（`CREATE TABLE IF NOT EXISTS`）；
3. 登录成功：`session_regenerate_id(true)` → `$_SESSION['user_id'] = $uid` → `redirect('../user/dashboard.php')`；
4. 已登录用户绑定：读取 `current_user()`，成功后跳转 `../user/profile.php`；
5. 登录页按钮：在 `user/index.php` 中按插件返回的可用类型渲染；
6. 回调必须校验 `state` / 来源，防止 CSRF 与账号劫持。

## 11. 支付插件约定

参考实现：`plugin/epay/`、`plugin/alipay/`、`plugin/wechat/`、`plugin/balance/`。

1. `cat` 设为 `pay`，业务入口为 `pay.php`；
2. 公共签名 / HTTP 逻辑可复用 `plugin/common/common.php`；
3. 创建支付时写入订单支付渠道与交易号；
4. 异步回调必须验签、校验金额与订单状态，成功后更新订单并返回平台要求的响应体；
5. 回调需幂等，重复通知不得重复加款；
6. 余额支付需在事务内扣减，失败整体回滚。

## 12. 实名认证插件约定

参考实现：`plugin/builtin/`。

- `cat` 设为 `realname`；
- 姓名 + 身份证号本地校验（GB11643 校验位），敏感字段用 `sec_encrypt()` 存储；
- 审核结果写库并记录审计，前台只展示脱敏信息（`sec_mask_idcard()`）。

## 13. 模板插件

`cat = template` 的插件由首页 `index.php` 渲染，核心文件为 `home.php`。完整规范见《主题开发文档》。

## 14. 安全规范（必须）

1. 输出一律 `e()` 转义；富文本需白名单过滤；
2. 所有 SQL 使用参数化；
3. 所有写操作校验 CSRF；
4. 密钥、Token 不得输出到前端或日志；
5. 外部请求设置超时并处理失败，不能阻塞页面；
6. 上传文件需校验类型与大小，禁止可执行脚本；
7. 不在插件中读取或输出后台目录、数据库配置等敏感信息；
8. 保留系统版权与「关于系统」入口。

## 15. 调试与排错

| 现象 | 排查 |
| --- | --- |
| 商店不显示插件 | `Plugin.php` 是否直接 `return` 数组、`code` 是否为空、目录是否在 `plugin/` 下 |
| 插件不可安装 | `installable` 是否为 1、状态是否为 3 |
| 配置保存不生效 | 是否已启用；键名是否被其他插件覆盖；是否读取了正确的 `plugin_cfg_get()` |
| 密钥读取为空 | `password` 类型留空不会覆盖旧值；检查 `sys_config` 对应键 |
| 页面 500 | 先执行 `php -l Plugin.php`，再查看 PHP 错误日志与 `runtime/` 日志 |
